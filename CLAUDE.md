# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

ziggui is a Zig 0.17 SwiftUI-style GUI library: a pure-Zig renderer (layout, text, themes, a software rasterizer and a GPU scene), the views on top of it, and an SDL3 runtime for windows. Since 1.0.0 it holds what used to be the separate `../zigui` (folded in from zigui `53d5d6a`; zigui is superseded and gets no further changes). Apps in `../` (ziggit, zigagent) depend on ziggui and import one module, `ziggui`.

All Zig code follows `../styleguide/ZIGSTYLE.md` (a sibling checkout and its own repo; never edit it from here). The guide is authoritative: fix the code, never the guide. The two standing exceptions (view constructors as free functions, C.1.a; entry-point-only tracing, D.3.a) are described under Architecture conventions. Apps built on ziggui follow `../styleguide/GUIDESIGN.md`; its kit rules (A.1.c, B.4, C.1.c–d, C.2.b, E.4.d) bind ziggui too.

**Follow SwiftUI's naming wherever SwiftUI has an equivalent**: `HSplitView`/`VSplitView`, `DisclosureGroup`, `GeometryReader`, `NavigationPath`, `SortOrder` (`.forward`/`.reverse`), `CommandMenu`, `MenuBarExtra`, `.clipped()`. Invent a name only when SwiftUI has none (`Chip`, `DiffView`).

## Build / Test

- Build: `zig build` (installs the static library of the core `ziggui`)
- Tests: `zig build test --summary all` — four test compiles (`renderer`, `views`, core `ziggui`, `gallery`), none links SDL or opens a window. `-Dtest-filter=<text>` filters them.
- SDL runtime tests: `zig build test-sdl --summary all`, a separate step (`test` never builds it, so `test` stays headless): one test compile rooted at `src/sdl` (`SdlTests` in `build.zig`), built and linked through `Modules.runtime` as for an app, so it compiles SDL. Natively it runs the tests (none opens a window); for a foreign `-Dtarget` it compiles and links them without running, so `zig build test-sdl -Dtarget=x86_64-windows` / `x86_64-linux-gnu` checks that platform's code. `src/sdl/module.zig`'s test references every runtime struct's declarations and instantiates the generic `EventLoop` and `PanelSpecification`, except `Cocoa`, `Win32` and `StatusNotifier` off their own OS, so each target analyzes what it builds, called or not. Declared, like the gallery, only for the root build and for macOS, Windows and Linux; `-Dtest-filter` applies.
- Gallery: `make demo` (`zig build run-gallery -Doptimize=ReleaseFast`; `ARGS="--dark"`). It opens a window and blocks: never run it from an agent; use the headless check.
- Headless check: `zig build gallery -Doptimize=ReleaseFast`, then `zig-out/bin/ziggui-gallery --screenshot out.bmp [--section <n>] [--theme <n>] [--accent <n>] [--dark] [--menu <n>] [--sheet] [--alert] [--popover] [--passthrough] [--options-menu] [--find] [--dialog] [--select] [--gpu] [--bench <n>]` (see `gallery/main.zig` for which flags need which section), then `sips -s format png out.bmp --out out.png` to look at it. The software rasterizer is deterministic: a refactor must leave every screenshot byte-identical, so render the sections before and after and `cmp` them. `--gpu` draws the same frame (same build, theme and size) through the real SDL_GPU pipeline offscreen, with no window (Metal works headless on macOS), and exits non-zero if no GPU device starts. It is the verification loop for a GPU change: diff its BMP against the software one. They agree to within 1 LSB a channel except blurred materials (up to 3: the software path box-blurs, the GPU path samples) and a few edges under overlay scrims (2). An unscaled glyph's quad starts on the whole pixel the software rasterizer starts it at (`GpuScene.glyphQuad`); left fractional, the GPU's 1/256 px vertex snapping put glyphs just past a half pixel one pixel off. `--bench <n>` draws the frame `n` more times and prints ms/frame, read back to RGBA8. With `--gpu` that is a full GPU sync.
- Gallery build options: `-Dsdl3-prefix=<dir>` links a prebuilt SDL3 (`include/`, `lib/`) instead of building the release; `-Dwindows-console` keeps a console on Windows (the gallery is a GUI-subsystem executable otherwise).
- Cross builds: `zig build gallery -Dtarget=x86_64-linux-gnu` / `x86_64-windows` / `aarch64-linux-gnu`. Zig only compiles what is referenced, so the Linux and Windows branches of `src/sdl` are only checked by a cross build: the gallery's for what it calls, `test-sdl`'s for the rest. An explicit macOS `-Dtarget` needs the SDK; the gallery resolves it through zigbuildx's `Xcode.initFor`.
- Format: `make format`. Lint: `make lint` (zlint against `../styleguide/zlint.json`, warnings are errors)
- Pre-commit gate: `make validate` (clean, format, lint, build, test)
- `format`, `lint`, `validate` and `buildxpin` come from `-include ../styleguide/Makefile.in`. The `Makefile` sets `ZIG_DIRS := src gallery build`; add any new source root there.
- Docs: `make docs` (`zig build docs`, rooted at `src/root.zig` with the module barrels staged as `root.zig`; see `src/root.zig` below; serves on 127.0.0.1:8080)
- The version lives in `build.zig.zon` `.version` and nowhere else (`ziggui.version` reads it); `make tag` tags and pushes it.
- After a change to a widget the apps use, rebuild ziggit and zigagent with `-Dapp` and compare their `--screenshot` output before and after (see each app's CLAUDE.md for the arguments). Their builds run zigbuildx's sibling sync, which `git fetch`es/`pull`s clean sibling repos.

## Module layout

Three build modules under one public one. Each directory has a `module.zig` barrel; a file imports its directory's barrel as `mod` and other build modules by name.

- `src/renderer/` — build module `renderer`: pure Zig, no C, no views. Barrel re-exports every type flat.
  - `geometry/`: `Point`, `Size`, `Rect`, `EdgeInsets`, `Alignment`, `HorizontalAlignment`, `VerticalAlignment`, `Axis`.
  - `layout/`: `Node` (and `StackNode`, `PaddingNode`, `FrameNode`, `SpacerNode`, `MeasuredNode`), `Proposal`, `SizingHints`, `LayoutResult`, `Direction`, `SpaceDistributor` (stack space allocation), `LayoutEngine` (`shared().measure`/`arrange`, the measure cache).
  - `render/`: `Color`, `Rgba8`, `Canvas` + `DrawCommand` (the renderer-agnostic seam both backends consume), `Framebuffer`, `Rasterizer` (software, SDF anti-aliasing; tests and the software fallback), `GpuScene` + `Instance`/`Step`/`TextureAtlas`/`AtlasUpload` (pure translation of a canvas for the GPU).
  - `state/`: `State(T)`, `Binding(T)`, `Observer`, `Animator`, `Easing`, `Tween`.
  - `text/`: `TtfFont` (TrueType parser and rasterizer; it treats font bytes as untrusted: every read is bounds-checked, tables and glyphs are validated in `parse`, composite glyphs have a work budget, and a malformed glyph draws empty rather than panicking), `GlyphCache`, `TextShaper` (measure, wrap), `Font`, `FontSet` (a face per weight/italic/mono), `TextPainter` (`shared()`: draws glyphs, text gamma), `Icon` (the Lucide set, camelCase variants; `IconName` at the root).
  - `theme/`: `Theme` (`Theme.default`), `Palette`, `Metrics`, `Typography`, the `Painter` vtable with `Surface`/`ControlState`/`Role`, `ThemeFamily` (`all`, `forScheme`), and the families `MacosTheme`, `Windows10Theme`, `Win2000Theme`, `KdeTheme`, `MuiTheme`.
  - The bundled fonts (`assets/fonts`: Inter, JetBrains Mono, Lucide, Noto Emoji) are anonymous imports on this module (`@embedFile("inter_font")` …), wired in `build.zig`.
- `src/views/` — build module `views` (imports `renderer`). Everything is a view.
  - `core/`: the engine. `View` (fluent modifiers) over `Kind`/`Modifiers`; `ViewLowering` (View → layout node), `ViewPainter`/`ControlPainter`/`TextViewPainter` (paint into a `Context`), `ViewRenderer` (`measure`, `render`, `renderInto`, `renderScaled`, overlays and popovers); `Screenshot` (`render(allocator, state, State.body, ScreenshotOptions)`: a body built for `frames` frames, default 2, with the theme and size published as the window's, the last rasterized to RGBA8; `bmp` encodes it), the headless `--screenshot` of the gallery and both apps; `Callback` (`init` a method, `action` a function, `select` a selection, `tagged(T, context, method, tag)` a method that also gets a tag, as UIKit's target-action reads the sender's `tag`: one handler for every row of a list, the (context, tag) pair in the build arena; use it rather than a per-widget struct for a row's remove or tap; `attempt(T, context, method, what)` a method that can fail: a tap cannot return an error, so the failure is logged as `what`), `HoverCallback`, `DragCallback` (`function` gets the deltas; optional `begin(context, tag)` when a press arms it, `end(context)` once on mouse-up from `PointerInput.endDrag`, before the global `drag_end` hook); `ScrollState`; `Context` and what painting collects (`HitRegion`, `HoverRegion`, `HitAction`, `OverlayRequest`, `A11yNode`). Singletons with `shared()`: `BuildScope` (the frame's arena, `BuildTokens`, theme, viewport, wrap cache, the app's token provider (`setTokenProvider`: `setTheme` then publishes `provider(theme)` instead of `BuildTokens.fromTheme(theme)`; null restores it); `begin` calls `WrapCache.beginFrame`, the only place the wrap cache evicts, so layouts handed to hit regions stay valid through the frame), `PointerInput` (tap, drag, hover, scroll, click modifiers; taps fire on the press, and a plain tap (callback, select; not a toggle or stepper, which change on the press) that arms no drag of its own also arms the nearest `onDrag` region beneath it under the point when that region holds the whole tapped region (and no overlay's `.dismiss` scrim lies between), so a tappable row inside a draggable one both taps and drags, while a sheet's button or a context menu's dismiss area over a row never drags it), `Focus` (focused field, caret), `FrameClock` (frame time, scrollbar fade), `TextSelection`, `TextContextMenu` (with `ClipboardOperations`). `Focus`, `TextContextMenu` and `PointerInput` hold `*TextFieldState` pointers across frames, so `TextFieldState.deinit` calls their `forget`; a test that focuses a field clears focus before the field goes. A selectable text's identity is its text plus its ordinal among identical texts in build order (`BuildScope.selectionOrdinal`), so repeated paragraphs select apart; a list that builds only its visible rows gives each row `.selectionId(id)` instead. `Accent`. `Screenshot`/`ScreenshotFrame`/`ScreenshotOptions` (headless frames). Test fixtures `TestCanvas`, `TestEnvironment`.
  - `controls/`: view constructors — `Text`, `RichText*`, `WrappedText`, `Button*` (`ButtonKeyed`: the shortcut drawn as a key cap inside the button, `ButtonData.shortcut`, painted by `ControlPainter.paintKeyCap` (`KeyCapColors`) with the anatomy of a `KeyCap` view: ground, hairline border (a bevel on a chiseled theme), the theme-scaled 4pt corner; its colors are the label color at `ControlMetrics.button_key_*_alpha`, so the cap reads on the button's fill), `Toggle`, `Slider`, `Stepper`, `ProgressView`, `Picker`, `SegmentedControl` (composed: equal segments from a depth stack of every title hidden under the visible one; `.fixedSize()` by default, a caller's `.frameMaxWidth()` stretches it), `TextField`, `TextEditor`, `Label`, `Badge` (+ `BadgeTone`), `KeyCap`, `Image`, `Icon`, `IconButton`, `LoadingDots`, `Drawing` (+ `Pen`), shapes, `LinearGradient`.
  - `containers/`: `VStack`/`HStack`/`ZStack`/`ForEach`, `Spacer`, `Divider`, `Empty`, `ScrollView*`, `GeometryReader`, `List`, `LazyVGrid`/`LazyHGrid`, `TabView`, `NavigationSplitView`/`NavigationLink` (+ `NavigationPath`), `Menu`/`ContextMenu`, `Sidebar`, `RadioGroup`, `Table`, `DataTable` (+ `SortOrder`, `SortColumn`), `SelectableRow` (+ `SelectableRowStyle.selectionText`), `ReorderableRow(content, &state, index, count, row_height)` over the app-owned `ReorderState` (`reorder_state.zig`, with `ReorderMove` above it: `dropIndex`, `isDragging`, `takeMove`, `cancel`, `ReorderMove.apply`), `PaneHeader`, `SettingRow`. `ReorderableRow` wraps `content` in a depth stack carrying the opacity and `.onDrag`, so the content's own `onTap`/`onSecondaryTap` stay; the drop line is a 2pt `accent_mark` layer on row `dropIndex`'s top edge (the last row's bottom edge for `count`). Its drag handler's context is the state, never the build arena (an armed drag outlives the frame), and the row index rides `DragCallback.tag`.
  - `text/`: `Span` and the rich-text layout (`RichLayout`, `RichRun`, `RichLine`, `RichFaces`), `TextFieldState`, `TextLines`, `EditorMetrics` (advances through the fallback fonts, as drawing does). Every forward step over UTF-8 goes through `TextLines.nextCodepointEnd` (a sequence that does not decode is one byte), matching the renderer's `CodepointIterator`, so caret stops and drawn glyphs agree on invalid text. The event loop's field keys follow the platform: on macOS ⌘←/⌘→ go to the line's start and end (`home`/`end`) and ⌘↑/⌘↓ to the text's (`moveToStart`/`moveToEnd`), Shift selecting; elsewhere Home/End. A one-line `TextField` scrolls sideways only as far as keeps its caret in view while focused (the start shows otherwise): the offset is `TextFieldState.scroll_x`, kept across frames by the painter (`TextViewPainter.followCaret`), so a caret moving inside the visible part leaves the text still, as a native field does. It clips its text, selection and caret to itself, so a long value never draws past the field. A `.secure()` field draws a dot per character and its selection over those dots (⌘A shows), mapping byte offsets to codepoints as the caret does (`TextViewPainter.secureOffset`: a byte that does not decode is one dot). Its painter sets `TextFieldState.secure`, so its text is never copied or cut (keys or context menu), its `selectedText` is always empty (so an app's own Edit menu cannot copy it either), its accessibility value is empty, and it is wiped from memory it leaves (`setText` wipes the whole buffer, deleted bytes past the end included; growth; `deinit`; a paste's copy too). An app that fills a secure field with a stored secret before its first frame sets `secure = true` first. The event loop stops draining the queue after a mouse press, so a click queued behind one that removed a row (and its fields) meets the next frame's regions.
  - `chat/`: `StatusMark` (`StatusMarkState`), `DisclosureGroup`, `Chip`, `CodeBlock`, `Quote`, `Bubble`.
  - `panes/`: `VirtualList`, `VirtualListBoth`, `DiffView`, `TableHeader`, `TableRow`; `DiffLine` (`hunkCount`, `hunkRow`, `revealHunk`, `wrap`, `wrapColumns`, `anchorAt`, `offsetAt`), `DiffAnchor`, `DiffLayout` (a row's measures, shared by the view and `wrap`), `RowRange`, `IndexCallback`. `VirtualListBoth` sizes rows to the row the caller names `widest`, built once more at zero height and `.clipped()` (text can't be measured while views are built), so the sideways scroll stays put as it scrolls down. `DiffView` is built on it: lines are never cut, the gutter scrolls with the text. To wrap, the caller passes `DiffLine.wrap(arena, lines, DiffLine.wrapColumns(digits, scroll.viewport_width))`, `digits` being `DiffLayout.digitsOf(lines)`, counted once per diff (it reads every line), not per frame: rows that continue a line (`continued`) have no numbers or marker and are never a hunk or file of their own, so hunk indices and `revealHunk` hold; the cell is `DiffLayout.cell_width`, the bundled mono face's advance (text cannot be measured while views are built); cells are counted, and lines split, with `TextLines.nextCodepointEnd`, so a bad byte is one cell and the text around it is never cut. The caller keeps the wrapped rows until the diff or the column count changes (ziggit's `WrappedRows`), and carries `scroll.offset` across a re-wrap with `DiffLine.anchorAt` on the old rows and `offsetAt` on the new: the offset is in points, so the rows above it would otherwise move it to other text. The pass over the whole diff (gutter digits, widest row, hunk starts) runs once per diff, not per frame: `DiffIndex` keeps it for the diff shown last, keyed by a hash of every line, and a frame binary-searches it for the rows in view.
  - `split/`: `HSplitView`, `VSplitView` on `GeometryReader` and `.clipped()`; `SplitState` (`size` is what the user last dragged, -1 until then; layout clamps without writing back).
  - `hover/`: `HoverPopover(content, state, id, details)`; `HoverState` (`shows` after `delay_ms`, `waiting` before it — the app keeps its loop awake then, a resting pointer sends no events). `enter` only records the row; `HoverPopover` calls `stamp` from the first frame built after it, because a motion event after an idle wait would otherwise carry the previous frame's `FrameClock` time and skip the delay. Mark the list `.popoverPassthrough()` so a click on another row reaches it.
  - `menu_bar/`: `MenuBar` (drawn in the window where there is no global menu bar), `MenuBarMenu`/`MenuBarItem`, `MenuBarMenus` (both forms and the fold width), `MenuBarOptions`, `MenuBarState`/`MenuBarKey` (the app forwards raw key-downs, key-ups and presses to `keyDown`/`keyUp`/`pointerDown`), `SdlKey` (SDL3 keycodes and modifier bits as named constants, so key handling stays headless — never write a raw keycode), `TestMenus` (fixture).

one field's chrome (`raised`, `line_strong`, radius 6), in the Forms section. `FileBrowser(&state, focused)` over `FileBrowserState` (`file_browser_state.zig`, with `FileNode`, `FileNodeKind`): one local folder read through the `std.Io` the app hands it, off the UI thread when that `Io` can run work concurrently (`Io.concurrent` on a `FolderListing`; an `Io` that cannot, such as `Io.Threaded.global_single_threaded`, lists in place, at once): `open`/`refresh`/`up`/`enter` start a listing (one asked for while another runs replaces it when that lands), `FileBrowser` calls `poll` as it builds to adopt a landed one, which wakes the window as it lands (`FrameClock.wake`, whose handler the SDL loop installs as it starts: `App.wake` from any thread; a no-op headless), so the app needs no busy check, and `wait()` blocks until it lands (tests, a first frame) (folders first, then files, by name, case aside; anything but a folder or a regular file left out; a folder costs no stat, a file or link one), a path bar with an up button and a "Hidden" toggle (`show_hidden`, a `State(bool)`), selectable rows on a `VirtualList` (only the rows in view are built; a tap selects, a double-click opens a folder; the app follows a keyboard `move` with `state.scroll.reveal`); the app routes keys to `move`/`enter`/`up` and reads the pick, a file or a folder alike, with `pickAlloc` (the folder on show when nothing is selected). A folder that cannot be read keeps the one on show and sets `failure`. It exists because SDL's, Windows' and GTK's dialogs cannot pick "a file or a folder" in one; the gallery's File Browser section (`Section.files`, `Kit.filesPanel`, over the working directory through `std.Io.Threaded.global_single_threaded`, since the gallery has no `Io` of its own).

  - `view_engine_test.zig`, `integration_test.zig`: pipeline tests across the whole module.

It re-exports the barrel; don't add code to it. The barrel re-exports from the `renderer` and `views` modules, which autodoc would root at an arbitrary file the same way (and then fail to resolve `views.View`), so `build.zig`'s `Docs` builds the site from a staged copy of `src/renderer` and `src/views` with each barrel also saved as `root.zig`. - `build/sdl_build.zig`: `SdlBuild.library`, SDL3 3.4.20 built from the official release tarball (the lazy `sdl` dependency; source lists and config ported from castholm/SDL v0.6.1, MIT). - `build.zig`: `Modules` declares `renderer`, `views` and the core `ziggui`; `Modules.app` builds `sdl` plus the app `ziggui` once per build graph (memoized), and `Modules.runtime` returns that `sdl` module (the `test-sdl` root). `pub fn linkApp(ziggui_dep, options)` returns the app `ziggui` for an executable; tests import `ziggui_dep.module("ziggui")`, the core one. Only executables (and `test-sdl`) compile and link SDL, and a dependent package fetches it only through `linkApp`; ziggui's own root build declares the gallery and `test-sdl` (`AppSteps.declare`, which reads `-Dsdl3-prefix` and the SDK once for both), so its first configure fetches the SDL tarball lazily, but its `test` step never compiles or links SDL.
- `gallery/`: the component gallery. Barrel `gallery/module.zig`, imported as `gallery`; it imports `ziggui` only. `Gallery` holds all state and builds the view tree; `Showcase` (the controls, text, shapes, layout, table, text editor, overlays, effects, navigation and geometry sections), `Editor` (the editor section) and `Kit` (Badges & Keys, Forms, Rows & Headers, Reorder, File Browser: sections 18–22) are its parts; `Platform` holds the window hooks `main.zig` fills from `ziggui.App`; `--screenshot` and the tests draw headless with `ziggui.Screenshot` over `Gallery.body`. `--gpu` and `--bench` build with `ziggui.ScreenshotFrame` (the same build `Screenshot.render` uses) and draw its commands through the GPU or time them. Keep the two in step: `--bench 1` without `--gpu` must give the same bytes as plain `--screenshot`. Built twice: on the core `ziggui` for tests, on the app `ziggui` for the executable. Every new component gets a gallery section: a `Section` variant (appended, so existing indices keep their screenshots), its `label`/`icon`, and a case in `Gallery.panel`.
- `fixtures/`: fixed files the gallery and checks refer to, so what they show is the same on every run (`fixtures/README.md`). `file_browser/` is the folder the gallery's File Browser section opens: `gallery.fixtures_path`, set from the build root by `build.zig` (`Gallery.configOptions`, the `gallery_config` options), so the gallery finds it from any working directory; the screenshot differs between checkouts only in the path it shows. `.gitattributes` keeps line endings as committed, since file sizes show.
- `assets/`: `fonts/` (embedded), `icon/` (the gallery's Windows icon resource, `ziggui.rc`).
- `tools/icon/mkico.py`: turns a polygon SVG into `.ico`/`.png`/an iconset (from zigui); ziggit's and zigagent's `tools/icon` scripts use it.
- `zig-pkg/`, `.zig-cache/`, `zig-out/`: fetched or generated; never hand-edit.

## Architecture conventions

- **One import:** consumers import `ziggui` and write `ziggui.X`. An executable gets the app `ziggui` from `linkApp`, its tests the core one, both under the name `ziggui`. `ziggui.App` and the other `sdl` names exist only in the app build, so app code that calls them stays in executable-only modules. One compilation can hold only one of the two (Zig: "file exists in modules 'ziggui' and 'ziggui0'"), so an app module both the executable and the tests use is declared twice, once over each `ziggui`, as `build.zig` does for `gallery/`.
- **Layering:** `renderer` never imports `views`; `views` never imports `sdl`. A new paint primitive goes in `renderer/render` (both backends: `Rasterizer` and `GpuScene`/`Gpu`); a new view kind or modifier in `views/core`; a composed widget in its `views/` directory.
- **One `BuildTokens`** (`views/core/build_tokens.zig`), set with the theme by `BuildScope.setTheme`, including the colors only ziggui's widgets use (`label`, `separator`, the diff greens and reds, `warning`/`info`, the badge grounds `*_soft`, `accent_text`/`accent_mark`, `sunken`/`raised`, `line_strong`, `focus_ring`, `bar_background`), derived from the theme; the defaults are the macOS light theme's. An app with its own design system installs `BuildScope.setTokenProvider` (usually `fromTheme` with some roles changed). Add a token there, never to `Palette`, unless every theme family defines it.
- **One `Modifiers` bundle per view:** a modifier replaces the same modifier set inside a constructor (`.padding` on a `Badge` replaces its padding), so wrap a view in a stack to pad or frame around it. `.frameMaxWidth()` clears a `.fixedSize()` (that is how `SegmentedControl` stretches); `ViewPainter` descends the frame `.fixedSize()` adds before the frame and padding ones.
- **`GeometryReader` builds its content at paint time.** By then the build arena has ended, so the painter swaps `BuildScope.shared().allocator()` to the context's arena while the content builds; `tokens()` still reads the frame's theme. Split panes are framed to their size and `.clipped()`. The drag strip is registered after the panes because hit regions are tested last-registered-first.
- **`VirtualList` and the table rows build their stacks with `StackBuilder.fromSlice`**, not a `VStack` over a slice. A `VStack` changes spacing and alignment, which breaks the app screenshot match.
- **Singletons:** module-level state lives in a struct with a file-level instance and `pub fn shared() *Self` (`BuildScope`, `PointerInput`, `Focus`, `FrameClock`, `TextSelection`, `TextContextMenu`, `LayoutEngine`, `TextPainter`, `App`, `Panel`, `FileDialog`, `StatusItem`). Keep `threadlocal` where state was thread-local.
- **The ZIGSTYLE exception (C.1.a):** view constructors are free, PascalCase functions (`Chip(...)`, `HSplitView(...)`, `VStack(...)`). Only view constructors are exempt: every other function, private helpers included, is a method on a struct (a private struct like `Table`, `DiffModel` or `Entries` holds the helpers). Each file with view constructors opens with the `//!` doc, then `// zlint-disable case-convention` under a comment saying why.
- Enum variants are camelCase (C.2: `.hunkHeader`, `.chevronDown`, `.roundedRect`); zlint does not check this. SwiftUI's alignment constants keep SwiftUI's names (`Alignment.topLeading`). Struct-local test types (`Probe`) open with `const Self = @This();` too.
- No local aliases (B.4.a): write `renderer.Rect`, `mod.View`, never `const View = mod.View;`, and in tests `mod.SdlKey.left_alt`, never `const left_alt = mod.SdlKey.left_alt;` (`const allocator = std.testing.allocator;` is the guide's own test pattern and stays). Imports go `std`, `log`, `mod`, then other modules (`renderer`, `views`, `sdl_c`) (B.2.b).
- Spell names out, locals, parameters and loop captures included: `title_bar_height`, `min_width`, `line_width`, `center_x`, `viewport_height`, `horizontalGradient`, `context`, `callback`, `environment`, `FrameSpecification`, never `title_bar_h`, `min_w`, `w`, `cx`, `hGradient`, `ctx`, `cb`, `env` or `FrameSpec`. Deliberate exceptions: `b: *std.Build` (every build script's convention), `catch |err|` and `io` (ZIGSTYLE's own idioms), `x`/`y`, `T` for a comptime type, `Color`/`Rgba8`'s `r`/`g`/`b`/`a` fields (spelled out they would clash with `Color.red`/`green`/`blue`), SwiftUI names (`midX`), unit suffixes (`_ms`), and anything that mirrors a C, SDL, Win32, Objective-C or D-Bus name (`hdc`, `num_samplers`, `SdlKey.left_ctrl`).
- One primary public type per file, the file named for it in snake_case (`build_tokens.zig` → `BuildTokens`). Supporting types go above it, last the primary: the types that are part of its API (its fields', payloads' and items' types: `Kind`'s `*Data`, `DrawCommand`'s payloads, `DiffLineKind`, `MenuBarItem`, `CommandItem`), even when callers name them to build or read it. A type with a life of its own, used by several types, gets its own file. A widget file (`chat.zig`, `panes.zig`, `split.zig`, `menu_bar.zig`, `title_bar.zig`, `controls/*.zig`, `containers/*.zig`) holds view constructors and no public struct: a public type the constructors take gets a file of its own (`split_state.zig`, `navigation_path.zig`). A supporting enum used only by one constructor stays beside it (`StatusMarkState`, `WindowButtonStyle`). Every struct and enum opens with `const Self = @This();`. Methods take `*Self`, or `*const Self` when read-only, including on enums. Order: `init`, `deinit`, public API, then private helpers.
- A `.foreground()` sets `foreground` for its subtree, and `Context.tint` for its own view only (never inherited); the button painter draws a `.plain` button's label in `tint` when set, so `ButtonRoled("Delete…", .plain, …).foreground(red)` is a red, unfilled button, while a color on a pane or row leaves its plain buttons alone. Other roles keep their painter colors.
- Stack space (`SpaceDistributor`): items with a natural size (a truncating text) are offered the room first, beside the fillers' minimums; fillers (`FlexItem.fills`: a `Spacer`, a max-width frame, max ≥ `fill_threshold`) share what is left. So `HStack{ name.truncated(), Spacer(), badge }` shows the whole name when it fits, as SwiftUI does. A stack of only one kind shares as before.
- `init` builds a local `const self = Self{ ... };` and returns it. Types that hold pointers into themselves are heap-allocated with `create`/`destroy` (`TestCanvas`, `EventLoop`).
- Import siblings only through the barrel. Compile-time invariants (`is_debug`) live in the barrels; never `@import("builtin")` elsewhere (executables read `gallery.is_debug`).
- View constructors allocate from `BuildScope.shared().allocator()` and read colors from `BuildScope.shared().tokens()`; they run once per frame inside `BuildScope.begin`/`end`, or at paint time inside a `GeometryReader`.
- Every file except `src/root.zig` declares `std.log.scoped(.ziggui_<file>)` (barrels `.ziggui_<dir>_module`). **The tracing exception (D.3.a):** only entry points (`main`, `App.run`, stateful `init`s, `Screenshot.render`) trace with `log.debug("{s}:{d} :: {s}", .{ @src().file, @src().line, @src().fn_name })`. View constructors and the per-frame methods they call would flood a Debug build's stderr every frame. A file with nothing to trace says so in its `test` block (`// Nothing here does I/O to trace.` and `_ = log;`).
- Errors: a view constructor cannot fail, so an allocation in the build arena ends `catch @panic("oom")`. Never swallow one with `catch ""`, `catch {}` or a fallback value. Format with `Allocator.print`, not the deprecated `std.fmt.allocPrint`.
- Every public declaration gets a `///` doc: struct fields, constants, and each barrel re-export included. A function's doc (E.1.b) is a one-line summary, a blank `///`, one `` - `name`: `` bullet per parameter (`self` too), then `- Returns:` whenever it returns a value. An error union counts (`- Returns: nothing; propagates allocation failure.`); a plain `void` function has no `Returns` line. There is no `Parameters:` header.
- Tests go after the `// Unit Tests` divider. They use `std.testing.allocator`, `defer` every `deinit`, and start with `test { std.testing.refAllDecls(...) }`. Draw and tap with `mod.TestCanvas` (`begin`, build, `end`, `render`, `tap`). A module's tests run only when it is a test root, which is why `build.zig` has one test compile per module.

## Zig 0.17 gotchas

- `@cImport` is gone: C headers go through `b.addTranslateC` and are imported as a module (`sdl_c`).
- **`@intCast` miscompile in Zig 0.17.0 (why `minimum_zig_version` is 0.17.1):** 0.17.0 emitted LLVM `trunc nsw` for `@intCast` from a signed integer to an unsigned one, a promise that the value also fits as a signed number, so a valid result in the top half of the unsigned range (128–255 in a `u8`) was poison and optimized builds folded code using it (`@as(u8, @intCast(@min(x, 200))) == 200` was false). The gallery's 18-section `Section` (5-bit tag, `.editor` = 17) hit it. 0.17.1 emits `trunc nuw`. If a ReleaseFast-only bug looks impossible, compare `--verbose-llvm-ir` against the Debug behavior.
- `zig fetch` and `zig build` can disagree on a tarball's hash when the cached tarball keeps its top-level folder; the `.sdl` hash in `build.zig.zon` is the one a clean fetch computes (`…LB1x…`, sources at the package root).
- `std.ArrayList(T)` is unmanaged (`.empty`, `append(allocator, x)`); `refAllDeclsRecursive` is gone; `std.process.Init` brings args and io to `main`; `allocator.dupeZ` is `dupeSentinel(u8, s, 0)`; array repetition is `@splat`.
- Inferred error sets plus recursion is a "dependency loop": recursive functions that allocate declare `std.mem.Allocator.Error!T`.
- `b.lazyDependency` is deprecated: use `b.dependencyLazy`.

## Project-state heads-ups

- ziggit and zigagent clone ziggui from `git@github.com:mlavergn/ziggui.git`, which must be pushed before a fresh app clone can fetch it.
- The gallery executable and `test-sdl` are declared only when ziggui is the root build (`b.dep_prefix.len == 0`), so packages depending on ziggui never fetch SDL for them. For a target SDL does not build for (anything but macOS, Windows, Linux) it is skipped with a `log.info`, so `lib` and `test` still configure.
- Environment variables the runtime reads: `ZIGGUI_SOFTWARE` (software rendering), `ZIGGUI_FRAME_LOG` (per-frame timing), `ZIGGUI_PANEL_DUMP=<path>` (dump the panel frame), `ZIGGUI_NO_FROST` (macOS: no window glass).
- Not yet tested by hand: dragging a split divider with a real mouse in a window. Unit tests cover a press arming the drag and the drag math, and the gallery's Split Views section is the place to try it.
- MSVC Windows builds follow castholm's SDL build but are untested (no MSVC headers on the Mac); mingw (`x86_64-windows`) is the checked target.
