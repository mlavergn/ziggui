# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

ziggui is a Zig 0.17 SwiftUI-style GUI library: a pure-Zig renderer (layout, text, themes, a software rasterizer and a GPU scene), a 3D scene graph (SceneKit's model, drawn by `SceneView`), the views on top of them, and an SDL3 runtime for windows. It is the GUI layer every native app in `../` shares, including the frame those apps draw alike (window chrome, menu table, notices, questions), so they look and behave the same. `README.md` is the overview (purpose, features, platforms, a first app); this file is the implementation. Since 1.0.0 it holds what used to be the separate `../zigui` (folded in from zigui `53d5d6a`; zigui is superseded and gets no further changes). Since 2.2.0 it also holds `../zigwebview`'s web view (`WebPage`, `WebView`, the WebKit backend; its browser shell became the gallery's Media Web section); zigwebview is superseded. Every app imports one module, `ziggui` (the apps are listed under Downstream apps).

All Zig code follows `../styleguide/ZIGSTYLE.md` (a sibling checkout and its own repo; never edit it from here). The guide is authoritative: fix the code, never the guide. The two standing exceptions (view constructors as free functions, C.1.a; entry-point-only tracing, D.3.a) are described under Architecture conventions. Apps built on ziggui follow `../styleguide/GUIDESIGN.md`; its kit rules (A.1.c, B.4, C.1.c–d, C.2.b, E.4.d) bind ziggui too.

**Follow SwiftUI's naming wherever SwiftUI has an equivalent**: `HSplitView`/`VSplitView`, `DisclosureGroup`, `GeometryReader`, `NavigationPath`, `SortOrder` (`.forward`/`.reverse`), `CommandMenu`, `MenuBarExtra`, `.clipped()`. Invent a name only when SwiftUI has none (`Chip`, `DiffView`). Where Zig cannot overload an initializer as SwiftUI does, use a modifier or an inherited style (`.pickerStyle()`, `.toggleStyle()`, `.pointerStyle()`) or an anonymous struct literal for SwiftUI's labeled arguments (`ProgressView(.{ .value = 0.4 })`), never a suffixed name. Known deviations, to rename in one app-wide change (agreed shapes): `RadioGroup` and `SegmentedControl` → `Picker(...).pickerStyle(.radioGroup)` / `.segmented`; `VDivider` → `Divider` turning vertical in an `HStack`; `Spinner`, `LoadingDots` → `ProgressView(.{})` with `.progressViewStyle(.circular)` / `.dots`, and `ProgressView(value)` → `ProgressView(.{ .value = value })`; `ScrollViewState(&state, view)` / `ScrollViewStateBoth` → `ScrollView(view).scrollPosition(&state)` / `.scrollAxes(.both)` (a stateless `ScrollView` already scrolls on its own, through `ScrollMemory`); `ButtonRoled(title, role, action)` → `Button(title, action)` with `.buttonStyle(.borderedProminent)` (`.bordered`, `.plain`) and `.role(.destructive)` / `.role(.cancel)`. Needing real behaviour first: `ButtonKeyed` → a `.keyboardShortcut(key)` that also fires the button; `SearchField` → `.searchable`; `IconSegmentedControl` → a `Picker` over icon labels; `WrappedText` → `Text` wrapping by default with `.lineLimit` (re-wraps every app's text); `SidebarStyled`, `NavigationSplitViewInset` → styles once those are view kinds. Renamed already (MIGRATION.md): `.textFieldStyle(.plain)` / `.textEditorStyle(.plain)` with `.contentMargins` (was `.chromeless`; `TextFieldStyle` and `TextEditorStyle`, inherited through `Context.applyEnvironment` as `.toggleStyle` is), `.foregroundStyle`, `.fontWeight`, `.monospaced`, `.font(.system(n))`, `.textSelection(.enabled)`, `.onTapGesture`, `SecureField`, `Font`/`FontFile`. Also to rename, found later (agreed shapes, Zig-friendly): `ContextMenu(trigger, &open, items)` → `trigger.contextMenu(&open, items)`; `RichTextSpaced(spans, m)` / `RichTextPreformatted(spans, m)` → `RichText(spans).lineSpacing(m)` / `.preformatted()`; `ScrollViewOffset` → `ScrollView(view).scrollPosition(...)` with `ScrollViewState`; `.onDrag(callback)` → `.gesture(DragGesture(callback))` (SwiftUI's `.onDrag` is drag-and-drop); `ButtonIconRoled` → `ButtonIcon(...).role(...)` with `ButtonRoled`; the frame modifiers (`.frameWidth`, `.frameHeight`, `.frameMinWidth`, `.frameMaxWidth`, `.frameMaxHeight`, `.frameAlign`, `.frameCap`) → `.frame(.{ .width, .height, .min_width, .max_width, .max_height, .alignment })`, `ziggui.infinity` for `.infinity` (the largest change: hundreds of call sites); `.truncated()` → `.lineLimit(1)` with the `WrappedText` change. Kept: `FileDialog` (the SDL layer), `HoverPopover`, and the names with no SwiftUI counterpart; and, as Zig cannot overload a name or label an argument without making every call longer, `.paddingInsets(insets)` (beside `.padding(n)`), `.backgroundFill`/`.backgroundMaterial` (beside `.background(color)`), `MinSpacer(n)` (`Spacer(minLength:)` would give every `Spacer()` an argument), `Icon(name, size, color)` and `ButtonIcon` (`Image(systemName:)`, `Button(_:systemImage:action:)`), `NavigationLinkIcon` and `DisclosureGroupAccessory` (SwiftUI's label builders), `FontToken` (SwiftUI's `Font.TextStyle`: ZIGSTYLE nests no supporting type, and `TextStyle` is the theme's), and stacks' `.spacing()`/`.alignment()` (SwiftUI's initializer labels, the modifier pattern above). `Font` is SwiftUI's (`.font(.body)`, `.font(.custom(name, size))`); the font file loader is `FontFile`.

## Build / Test

- Build: `zig build` (installs the static library of the core `ziggui`)
- Tests: `zig build test --summary all` — six test compiles (`renderer`, `scenes`, `views`, `charts`, core `ziggui`, `gallery`), none links SDL or opens a window. `-Dtest-filter=<text>` filters them.
- SDL runtime tests: `zig build test-sdl --summary all`, a separate step (`test` never builds it, so `test` stays headless): one test compile rooted at `src/sdl` (`SdlTests` in `build.zig`), built and linked through `Modules.runtime` as for an app, so it compiles SDL. Natively it runs the tests (none opens a window); for a foreign `-Dtarget` it compiles and links them without running, so `zig build test-sdl -Dtarget=x86_64-windows` / `x86_64-linux-gnu` checks that platform's code. `src/sdl/module.zig`'s test references every runtime struct's declarations and instantiates the generic `EventLoop` and `PopoverWindowSpecification`, except `Cocoa`, `Win32` and `StatusNotifier` off their own OS, so each target analyzes what it builds, called or not. Declared, like the gallery, only for the root build and for macOS, Windows and Linux; `-Dtest-filter` applies.
- Gallery: `make app` (`ARGS="--dark"`). It first builds the `ziggui` module (`make build`, `zig build`). On macOS it then builds `zig build gallery-app -Doptimize=ReleaseFast`, the gallery as `zig-out/ziggui Gallery.app` (`zigbuildx.App`: `Info.plist` from build.zig.zon, identifier `com.marclavergne.ziggui.gallery`, `assets/icon/zigz.icns`, unsigned, the executable signed ad hoc by the linker), and opens it with `open -n` (it returns at once; the app's output goes to the system log, not the terminal); elsewhere it builds the gallery (`zig build gallery -Doptimize=ReleaseFast`) and runs `zig build run-gallery -Doptimize=ReleaseFast` in the terminal (`gallery-app` lays a Linux build out as `bin/ziggui Gallery` with a desktop entry and icon). Either way it opens a window: never run it from an agent; use the headless check. `zig build gallery` still installs the plain `zig-out/bin/ziggui-gallery` the headless checks run.
- Install the gallery: `make app-install` (macOS only; `make install` is the same) builds the same bundle as `make app` and copies it to `~/Applications` (`APP_DIR=<dir>` puts it elsewhere), replacing any older copy.
- Headless check: `zig build gallery -Doptimize=ReleaseFast`, then `zig-out/bin/ziggui-gallery --screenshot out.bmp [--size <w>x<h>] [--workers <n>] [--section <n>] [--theme <n>] [--accent <n>] [--dark] [--menu <n>] [--sheet] [--alert] [--popover] [--passthrough] [--options-menu] [--picker-menu] [--find] [--replace] [--editor-style] [--dialog] [--select] [--rename] [--path-entry] [--search <text>] [--components] [--ray-traced] [--memos] [--gpu] [--bench <n>]` (see `gallery/main.zig` for which flags need which section), then `sips -s format png out.bmp --out out.png` to look at it. The software rasterizer is deterministic (see Verifying a change). `--gpu` draws the same frame (same build, theme and size) through the real SDL_GPU pipeline offscreen, with no window (Metal works headless on macOS), and exits non-zero if no GPU device starts. It is the verification loop for a GPU change: diff its BMP against the software one. They agree to within 1 LSB a channel except blurred materials (up to 3: the software path box-blurs, the GPU path samples), a few edges under overlay scrims (2), and scaled images and pictures (`Image(...).scaledToFit()`, `GraphicsContext.picture`: the GPU filters linearly, the software path samples, so the Image & Canvas section differs there by much more, and only there; and the Scenes section, which the GPU draws and the software path draws as its placeholder). An unscaled glyph's quad starts on the whole pixel the software rasterizer starts it at (`GpuScene.glyphQuad`); left fractional, the GPU's 1/256 px vertex snapping put glyphs just past a half pixel one pixel off. `--bench <n>` draws the frame `n` more times and prints ms/frame, read back to RGBA8. The run's report (the file written, the bench line) goes to standard output (`Frame.report`), whatever the build's log level. With `--gpu` that is a full GPU sync. `--size` draws at another size (980×660 points, one pixel each, by default; `--size 3840x2160` is a 4K window; a side past 16384 is refused). `--workers <n>` rasterizes through `ParallelRasterizer` on `n` workers (0: `WorkerPool.defaultWorkerCount`), as a window's software path does, into a framebuffer and RGBA buffer kept across `--bench`'s draws, as a window keeps them (without `--workers`, `--bench` times one thread the same way); its image is byte-identical to plain `--screenshot`'s whatever `n`. On a 20-core GB10, a 4K frame took about 22 ms on one worker and 3 to 5 ms on 16.
- Gallery build options: `-Dsdl3-prefix=<dir>` links a prebuilt SDL3 (`include/`, `lib/`) instead of building the release; `-Dwindows-console` keeps a console on Windows (the gallery is a GUI-subsystem executable otherwise).
- Cross builds: `zig build gallery -Dtarget=x86_64-linux-gnu` / `x86_64-windows` / `aarch64-linux-gnu`. Zig only compiles what is referenced, so the Linux and Windows branches of `src/sdl` are only checked by a cross build: the gallery's for what it calls, `test-sdl`'s for the rest. An explicit macOS `-Dtarget` needs the SDK; the gallery resolves it through zigbuildx's `Xcode.initFor`.
- Format: `make format`. Lint: `make lint` (zlint against `../styleguide/zlint.json`, warnings are errors)
- Pre-commit gate: `make validate` (clean, format, lint, build, test)
- `format`, `lint`, `validate` and `buildxpin` come from `-include ../styleguide/Makefile.in`. The `Makefile` sets `ZIG_DIRS := src gallery build`; add any new source root there.
- Docs: `make docs` (`zig build docs`, rooted at `src/root.zig` with the module barrels staged as `root.zig`; see `src/root.zig` below; serves on 127.0.0.1:8080)
- The version lives in `build.zig.zon` `.version` and nowhere else (`ziggui.version` reads it); `make tag` tags and pushes it.

## Verifying a change

`make validate` passing is necessary, not sufficient: Zig analyzes only what is referenced, and the headless tests never reach the SDL runtime's platform branches or the apps.

1. `make validate` (clean, format, lint, build, the six headless test compiles).
2. A change under `src/sdl`: `zig build test-sdl --summary all` natively, then with `-Dtarget=x86_64-windows` and `-Dtarget=x86_64-linux-gnu` (compiled and linked, not run), and `zig build gallery -Dtarget=x86_64-windows` / `aarch64-linux-gnu`. `Cocoa`, `ObjectiveC` and the AVFoundation player compile only on macOS, natively.
3. Anything that draws: render every gallery section (`--section 0` to the last) and the overlay variants (`--dark`, `--sheet`, `--alert`, `--popover`, `--menu 0`, `--find`, `--replace`, `--editor-style`, `--select`, `--rename`, `--path-entry`, `--options-menu`, `--memos` with `--section 15`, and `--picker-menu` with each `--theme`) before and after, and `cmp` each pair. A refactor leaves every one byte-identical; a deliberate change differs only where intended (look at both). A change to the software rasterizer (`Rasterizer`, `RasterPlan`, `ParallelRasterizer`, `RowBands`): every one also with `--workers 16`, byte-identical to the plain one, and a `--size 3840x2160 --bench` before and after. The File Browser section shows the checkout's absolute path, so a baseline built in another folder differs there only. A GPU change: diff `--gpu` against the software BMP (tolerances under Build / Test). A change to the 3D scenes' ray tracing (`MetalSceneRayTracer`, `scene_traced.metal`, the `shade` template; `VulkanSceneRayTracer`, `vulkan_interop.c`, `scene_traced.frag`, recompiled with `compile.sh`): `test-sdl`'s ray-traced tests, `--gpu --section 21 --ray-traced` looked at against its last version, and `--gpu --section 21` (rasterized) byte-identical but where intended, on macOS and on a Vulkan GPU with ray queries; on Vulkan also under the Khronos validation layer (`VK_LAYER_PATH=<its explicit_layer.d> VK_INSTANCE_LAYERS=VK_LAYER_KHRONOS_validation`, the test binary run directly, since the layer reports on stdout, which `zig build` takes), which must report nothing (its synchronization validation cannot see a ray query's read of a structure reached by address, so the barriers rest on the spec).
4. A change to anything the apps use, a public name above all: build every app in `../` (`zig build test --summary all`, then `zig build -Dapp`), and fix the apps in the same change (see Downstream apps). Compare the `--screenshot` output of those that have one before and after, each run from the same working directory (zigagent's top bar shows it); a baseline of an app's committed version builds in a scratch folder holding the app's files beside symlinks to its sibling dependencies, since a `build.zig.zon` path must be relative.
5. A new or changed function documents what it does in the E.1.b form (Architecture conventions); no function goes undocumented.

## Downstream apps

ziggit, zigagent, zigmcp, zigr2, zigiptv and zigcode depend on ziggui by path (`../ziggui`), so they build against this working tree, uncommitted changes included; zigbase is the template a new app starts from. Each declares its GUI module twice, over the core `ziggui` for its tests and over `linkApp`'s for its executable (zigmcp's `addGuiModule` is the pattern). They draw their frame with ziggui's shared pieces rather than their own copies: `WindowChrome`, a `MenuTable` constant, `NoticeText` and `NoticeBar`, `Confirm` and `ConfirmAlert`, `Key`, `DisplayText.clean`, `TextFieldState.wipe`, `HeadlessPlatform`; a piece more than one app needs belongs here, not in an app. ziggit, zigagent, zigmcp, zigr2 and zigiptv have a headless `--screenshot` (see each app's CLAUDE.md for its arguments); zigcode only builds and tests. Their builds run zigbuildx's sibling sync, which `git fetch`es/`pull`s clean sibling repos.

## Module layout

Five build modules under one public one. Each directory has a `module.zig` barrel; a file imports its directory's barrel as `mod` and other build modules by name.

- `src/renderer/` — build module `renderer`: pure Zig, no C, no views. Barrel re-exports every type flat.
  - `geometry/`: `Point`, `Size`, `Rect` (`aspectFit(width, height)`: SwiftUI's `.scaledToFit()` for an image or a video picture), `EdgeInsets`, `Alignment`, `HorizontalAlignment`, `VerticalAlignment`, `Axis`.
  - `layout/`: `Node` (and `StackNode`, `PaddingNode`, `FrameNode`, `SpacerNode`, `MeasuredNode`), `Proposal`, `SizingHints`, `LayoutResult`, `Direction`, `SpaceDistributor` (stack space allocation), `LayoutEngine` (`shared().measure`/`arrange`, the measure cache).
  - `render/`: `Color`, `Rgba8`, `Image` (`byteLength`, saturating; `isWhole`: an image whose pixels are fewer than its size says is never read, by either backend), `DisplayList` + `DrawCommand` (the renderer-agnostic seam both backends consume), `Framebuffer` (`clearRows`, `toRgba8Rows`: a band's part), `Rasterizer` (software, SDF anti-aliasing; tests and the software fallback; `render` walks the commands with one clip stack, copying nothing; `drawSelected(items, indices)`/`drawItem` draw a `RasterPlan`'s items; `limitedTo(rows)` paints only a `RowBand`, which narrows only the pixels a command visits, so a pixel's value never depends on the band), `RasterPlan` (`raster_plan.zig`, with `RasterClip` and `RasterItem`: the command list flattened once, on one thread: each drawing command with the clip stack it is under (a slice per push, shared), a scene replaced by its placeholder, and its rows' conservative reach (`min_y`/`max_y`, `mayTouch`), so a band skips what it cannot touch; `runEnd` ends a run at the next blur, the one command that reads pixels it does not draw), `ParallelRasterizer` (`parallel_rasterizer.zig`: a `Rasterizer` over a `WorkerPool`, or the calling thread with none; `drawFrame(background, commands, bytes)` clears, draws and converts each band while its pixels are in the core's cache (the stage's `DrawJob`), a blur splitting the frame into stages with the blur on the calling thread over every row between them; `clear`, `render` and `toRgba8` alone too; each stage's items sorted once into per-band buckets (`BandBuckets`, from each item's `min_y`/`max_y` through `RowBands.indexOf`), so a band visits only what may reach it rather than every item (a 4K frame is about 500 bands); byte-identical to `Rasterizer` whatever the worker count, which its test and the gallery's `--workers` check), `GpuScene` + `Instance`/`Step`/`TextureAtlas`/`AtlasUpload` (pure translation of a canvas for the GPU; `InstanceKind` names what an instance draws, `Instance.parameters[0]` as the shaders read it, so `Gpu`'s video underlays name `.image`/`.fill` rather than numbers). `eraseRect` cuts what is drawn back to transparent (destination-out: the rasterizer drops alpha by coverage; the GPU draws a fill instance in a `Step.erase` with `Gpu.erase_pipeline`), the hole a `VideoPlayer`'s picture shows through. `drawVideoFrame` (`DrawCommand.videoFrame`) draws a picture whose pixels change from frame to frame (a decoded video frame) and is never put in the atlas (keyed by pointer, it would show stale frames): the rasterizer draws it as an image; `GpuScene` gives it a `Step.frame` of its own, and `Gpu` keeps a texture per `key` (the player; `frame_textures`, up to `max_frame_textures` (8) a frame, freed `idle_video_frames` after its last draw; a picture past them, or one that cannot be had, is skipped, its black letterbox left, never the window's frame) drawn with the linear sampler the Windows underlays share (`Gpu.linearSampler`), uploading the pixels only when `generation` changed, so a paused video or a UI-only frame uploads nothing. A `Canvas` reaches it as `GraphicsContext.picture(rect, image, key, generation)`, for a picture too large for the atlas (a photo) or one whose pixels change: drawn through the current clip, so a rect larger than the view and offset zooms and pans it for a quad (the gallery's Image & Canvas section has a 2048 × 1536 one, dragged to pan); it shares the eight textures a frame with the video players. `drawScene` (`DrawCommand.scene`, a `SceneCommand`) draws a 3D scene into a rect, the scene an opaque pointer (`renderer` cannot import `scenes`): `GpuScene` breaks the stream with a `Step.scene` (rect, the clip's axis-aligned intersection, the scene) and keeps its placeholder's instances (`SceneCommand.placeholder`: the rect filled with `ground`, an isometric cube's nine edges in `ink`) in `SceneStep.placeholder`, drawn only where the GPU cannot draw the scene; the `Rasterizer` always draws the placeholder, under the clips around it.
  - `state/`: `State(T)`, `Binding(T)`, `Observer`, `Animator`, `Easing`, `Tween`.
  - `parallel/`: `WorkerPool` (persistent threads running one job at a time over task indices, a parallel `for`: `create(allocator, io, worker_count)` spawns `worker_count - 1` threads (one that cannot start is logged and left out), `run(T, context, function, task_count)` hands indices out from an atomic counter to them and the calling thread and returns when all are done; the threads sleep on the `io`'s futex between jobs, which `std.Io.Threaded.global_single_threaded.io()` serves; `defaultWorkerCount` the logical CPUs, at most `max_default_workers` (16); `create` makes at most `max_workers` (256), whatever it is asked, so a count from the environment never spawns thousands of threads; one job at a time, from one thread), `RowBand` (a half-open range of whole rows, `slice` its part of a row-major buffer), `RowBands` (`indexOf(row)` the band holding a row; `init(height, row_bytes, worker_count)`: bands of at most `cache_bytes` (256 KiB, measured best from 64 to 256 KiB on a GB10) of pixels so work over a band stays in a core's L2, at least `bands_per_worker` (4) a worker for balance, at least `min_band_rows` (4) rows; `band(index)`). Nothing in them draws: any per-row work splits with them.
  - `text/`: `TtfFont` (TrueType parser and rasterizer; it treats font bytes as untrusted: every read is bounds-checked, tables and glyphs are validated in `parse`, composite glyphs have a work budget, and a malformed glyph draws empty rather than panicking), `GlyphCache`, `TextShaper` (measure, wrap; a `.truncated()` text cut by `Context.truncateToWidth`, which draws nothing when not even the "…" fits, rather than an ellipsis past its frame), `FontFile` (a font file's face and its metrics: the bundled defaults, or bytes; `Font` is the view font, SwiftUI's name), `FontSet` (a face per weight/italic/mono; `familyCache(name, style)` draws a registered family from a cache of its own, made on first use over the set's own copy of the face, whose fallback is the bundled face of the same style then emoji, so ⌘ or an arrow a family lacks still draws; `FontRegistry.bundled_sans`/`bundled_mono` ("Inter", "JetBrains Mono") map to the bundled slots; an unknown name draws the bundled faces, warned once), `FontFamily` (a name and the TrueType bytes of `regular` and optional `bold`, `italic`, `bold_italic`), `FontRegistry` (`shared()`: the process's families by name, for every window and headless frame; `register(allocator, family)` at any time from the UI thread copies and parses each face (a face that does not parse, or a bundled name, refuses the whole family), replacing a family of that name for new text while keeping the old faces alive (glyph caches may point at them) until `reset`; `face(name, style)` (a missing style draws regular, bold italic trying italic then bold), `namesAlloc`, `familyCount`/`familyName`/`familyIndex` without allocating), `TextPainter` (`shared()`: draws glyphs, text gamma), `Icon` (the Lucide set, camelCase variants; `IconName` at the root).
  - `theme/`: `Theme` (`Theme.default`), `Palette`, `Metrics`, `Typography`, the `Painter` vtable with `Surface`/`ControlState`/`Role`, `ThemeFamily` (`all`, `forScheme`), and the families `MacosTheme`, `Windows10Theme`, `Win2000Theme`, `KdeTheme`, `MuiTheme`.
  - The bundled fonts (`assets/fonts`: Inter, JetBrains Mono, Lucide, Noto Emoji) are anonymous imports on this module (`@embedFile("inter_font")` …), wired in `build.zig`.
- `src/scenes/` — build module `scenes` (imports `renderer` for colors and images; `views` and `sdl` import it): an app-owned 3D scene graph after SceneKit, pure Zig. `math/`: `Vec3`, `Vec4`, `Mat4` (column-major, as the shaders read it, transforming column vectors; right-handed, the camera down -Z, depth 0 at near to 1 at far, as SDL_GPU's backends take it: `perspective`, `orthographic`, `lookAt`, `compose`, `inverse` (the identity for a singular matrix), `normalMatrix`), `Quaternion` (`fromAxisAngle`, `lookRotation`, `fromBasis`). `model/`: `Scene` (the app's: `init(allocator)` makes the root, `addChild(parent, node)` returns a `SceneNodeId` (slot and generation, so a removed node's handle finds nothing once its slot is reused), `remove(id)` takes its subtree (the root stays), `node(id)` to change it, `parentOf`, `worldTransform`, `walk` (the nodes not hidden, parents first, each with its transform composed parent first); `ambient`/`ambient_intensity`, `background` (the view fills it as UI before the scene), `point_of_view` (the node whose `SceneCamera` it is seen through; none: a default camera 5 units back along +Z), `camera_target`, `lighting_technique` (`SceneLightingTechnique`: `rasterized`, the default (shadow maps, no point-light shadows, no reflections), or `rayTraced`, drawn traced only where the GPU traces rays, else rasterized), `viewport` (where a `SceneView` last drew it, written by its painter as a `SceneViewport`: rect, visible part, frame number and window, so the gestures act only over the last frame's view)), `SceneNode` (`transform` (`SceneTransform`: position, rotation, scale in the parent's space), optional `geometry`, `light`, `camera`, a `material`, `casts_shadows`, `receives_shadows`, `hidden`, `opacity` (SceneKit's: multiplied down the tree by `walk` into `SceneVisit.opacity`, folded by `gather` into the shape's material alpha, so a faded shape is translucent (back to front, no shadow) and one at 0 is not drawn; lights and cameras unaffected); `lookAt(target, up)` in its parent's space), `SceneGeometry` (`box`, `sphere`, `plane` (XY facing +Z, as `SCNPlane`; turned -90° about X for a floor), `cylinder`, `mesh` (`SceneMesh`: the app's slices and `generation`; `validate` checks normals per position, whole triangles, indices in range); `key` (sizes, or a mesh's slices and generation), `bounds`, `build` into `SceneVertex`es (position, normal, uv; triangles counter-clockwise from outside)), `SceneMaterial` (`reflectivity`, 0 to 1, mirrored only when ray traced; sRGB `base_color` whose alpha blends, a `SceneTexture` (an RGBA8 sRGB `renderer.Image` with `generation` and `translucent`), Blinn-Phong `specular` and `shininess`; `isTranslucent`), `SceneLight` (`SceneLightKind`: `directional` along the node's -Z (`casts_shadows`; `angular_diameter`, the source's apparent size in degrees, softening ray-traced shadows away from their caster), `point` at the node with a `range` (`casts_shadows` and `radius`, ray traced only); color, intensity), `SceneCamera` (field of view in degrees, near, far; a degenerate one projects as the default), `SceneFrame` (`gather(allocator, scene, aspect)`: one frame for the GPU: opaque `SceneDraw`s, then translucent ones from back to front by their centers, at most `max_directional_lights` (4) and `max_point_lights` (8), the first in the walk kept, colors made linear (`linear`), the camera's view and projection, and each shadow-casting light's `shadowProjection`: an orthographic box along the light fitted across it to the receivers' bounds and along it to every caster's, null when nothing casts or receives; translucent shapes cast none). `camera/`: `SceneCameraControl` (`orbit` the point-of-view node about `camera_target` from a drag's points, its pitch short of straight up or down; `zoom` and `wheel` between `min_distance` and `max_distance`, a huge wheel turn bounded; each keeps it looking at the target; none without a point of view).

## Architecture conventions

- **One import:** consumers import `ziggui` and write `ziggui.X`. An executable gets the app `ziggui` from `linkApp`, its tests the core one, both under the name `ziggui`. `ziggui.App` and the other `sdl` names exist only in the app build, so app code that calls them stays in executable-only modules. One compilation can hold only one of the two (Zig: "file exists in modules 'ziggui' and 'ziggui0'"), so an app module both the executable and the tests use is declared twice, once over each `ziggui`, as `build.zig` does for `gallery/`.
- **Layering:** `renderer` never imports `scenes` or `views`; `scenes` imports only `renderer`; `views` never imports `sdl` or `charts`; `charts` imports only `renderer` and `views`. A new paint primitive goes in `renderer/render` (both backends: `Rasterizer` and `GpuScene`/`Gpu`); a new view kind or modifier in `views/core`; a composed widget in its `views/` directory; a chart in `charts/`.
- **One `BuildTokens`** (`views/core/build_tokens.zig`), set with the theme by `BuildScope.setTheme`, including the colors only ziggui's widgets use (`label`, `separator`, the diff greens and reds, `warning`/`info`, the badge grounds `*_soft`, `accent_text`/`accent_mark`, `sunken`/`raised`, `line_strong`, `focus_ring`, `bar_background`), derived from the theme; the defaults are the macOS light theme's. An app with its own design system installs `BuildScope.setTokenProvider` (usually `fromTheme` with some roles changed). Add a token there, never to `Palette`, unless every theme family defines it.
- **One `Modifiers` bundle per view:** a modifier replaces the same modifier set inside a constructor (`.padding` on a `Badge` replaces its padding), so wrap a view in a stack to pad or frame around it. `.frameMaxWidth()` clears a `.fixedSize()` (that is how `SegmentedControl` stretches); `ViewPainter` descends the frame `.fixedSize()` adds before the frame and padding ones.
- **`GeometryReader` builds its content at paint time.** By then the build arena has ended, so the painter swaps `BuildScope.shared().allocator()` to the context's arena while the content builds; `tokens()` still reads the frame's theme. Split panes are framed to their size and `.clipped()`. The drag strip is registered after the panes because hit regions are tested last-registered-first.
- **`VirtualList` and the table rows build their stacks with `StackBuilder.fromSlice`**, not a `VStack` over a slice. A `VStack` changes spacing and alignment, which breaks the app screenshot match.
- **On macOS video plays behind the window's surface, not in it** (Linux draws it in the surface, Windows under it; see the end of this item). The platform player draws its own picture (hardware decode, HDR, A/V sync); ziggui never sees a frame. Each frame the main window's context collects `VideoRegion`s (`Context.video_regions`, set by the loop only where `VideoBackend.presents`): a `VideoPlayer` erases its frame and registers its rect, the visible part (`Context.visible`) and corner radius, and `VideoBackend.present` places each player's picture there after the tree paints. On macOS that is an `AVPlayerLayer` in a layer-hosting `NSView` added to the content view *below* SDL's Metal view, whose `CAMetalLayer` is made non-opaque (as `Cocoa.frostWindow` puts glass behind a panel), so everything painted after the `VideoPlayer` (controls, a buffering card, sheets) composites over the picture; a player no view showed this frame is hidden. Placement compares each frame with the one AppKit holds (never a cache of what was last asked: a full-screen transition moves the views behind our back), sets only the host layer's size (it is the container's own layer, which AppKit positions; setting its frame put it at the window's corner once a full-screen exit reordered AppKit's sync), makes SDL's Metal layer non-opaque when a picture is first added and while a resize settles, and settles resizes with `ResizeSettle` (`resize_settle.zig`): after the content view's size changes (its first size, at launch, is not a change) it asks `FrameClock` for a frame `settle_ms` (600) after the last change, again every frame until then (the clock keeps only the earliest request, which an earlier one such as a hover hint would win), so the pictures are placed after a full-screen transition, which sends no event at its end. `AppKitNativeHost` compares with AppKit's frames the same way and settles with its own `ResizeSettle`. Where nothing is collected (headless, a stub platform) a `VideoPlayer` is a black frame with a video glyph. While its player plays, waits, seeks or loads its item it asks for a frame every `Player.refresh_interval_ms`, so labels drawn from `observe` keep up; the picture itself needs no ziggui frames. The native player is made on first need (`Player.nativeHandle`), so a `Player` set up before `App.run` gets what it was asked for; making it hands it everything asked so far (volume, mute, output, item, seek, rate), so a change that makes it sends nothing more (`Player.handleForChange`), else an item would load twice; it keeps the backend it was made with, so `deinit` after the loop ends still frees it (`VideoBackend.uninstall` takes the pictures out of the window first). Call players from the UI thread. A new platform implements the same declarations as `AvFoundationPlayer` (`backend`, `presents`, `present`, `detachAll`, and optionally `underlays`). **Windows is the exception:** SDL's swapchain is opaque to the desktop compositor, so nothing behind the window can show. `MediaFoundationPlayer` runs `IMFMediaEngine` in frame-server mode, and `present` has each shown player's engine write its newest frame into a WIC bitmap (`OnVideoStreamTick`, `TransferVideoFrame`) and hands the bitmap's BGRA rows, read under a lock kept until the next frame (packed into a buffer of the player's only when WIC pads them), to a `VideoUnderlay`: no pass over the frame swaps or copies it on the UI thread but the upload's; a player's rate drops to 0 at the item's end, as AVPlayer's does; the loop hands `VideoBackend.underlays()` to the renderer, which fills only what the surface left transparent in the hole (`Gpu.drawUnderlays`: an `under_blend` pipeline over the prim shaders, one BGRA texture per player, uploaded only for a new frame, its fourth byte ignored, since the blend weighs the picture by the scene's alpha; software: `VideoUnderlay.composite` on the RGBA buffer, whose alpha is straight: what was painted counts by its coverage, the picture by the rest), so controls painted over the hole stay on top. While a shown player plays, `present` asks for a frame every 16 ms. On Linux the picture is in the surface instead: on X11 a child window always covers its parent, so a window for the picture would hide the controls, and `GstreamerPlayer` hands its frames to `VideoPlayer` (`PlayerBackend.frame`, `DisplayList.drawVideoFrame`), which works on Wayland and with the software renderer alike.
- **On Linux a native view is an X11 child window of SDL's** (`GtkNativeHost`): each `GtkWidget` sits in a popup `GtkWindow` (no window manager) holding a `GtkLayout` (which asks no room of its own, so a view cut by a scroll view never grows the window), realized, its GDK frame sync turned off (`gdk_x11_window_set_frame_sync_enabled`: GDK otherwise waits after each frame for the compositor's `_NET_WM_FRAME_DRAWN`, which never comes for a window inside another client's, so GTK drew one frame and WebKit never showed), and `XReparentWindow`ed into SDL's window, moved and resized in GTK units (points × `SDL_GetWindowDisplayScale` ÷ GTK's scale); corners stay square. GDK's events pass through `filterEvent` (`gdk_event_handler_set`) first: a press in a view's window `claim`s it (X input focus with `XSetInputFocus`, a synthetic focus-in via `gtk_widget_send_focus_change`, since a popup gets no focus events and WebKit takes no keys in a window GTK thinks inactive, ziggui's `Focus` cleared), and a key with Ctrl or Super there goes to the app's key handler first. X hands a key to the window under the pointer when it lies inside the focused one, and SDL 3.4 reads keys through XInput2, so a view's window selects key events only while it holds the keyboard (`listenForKeys`), else typing in a ziggui field with the pointer on a view would go to the view. `hasFocus` asks the server (`XGetInputFocus`); after the user leaves and returns, the window manager focuses SDL's window, and the next frame gives the keyboard back to the view that held it. SDL never sees a press on a view (X sends it to the child), and GTK's key bindings copy and paste, so `performEdit` does nothing. Not under Wayland: GTK cannot place a window inside a foreign surface (run with `SDL_VIDEO_DRIVER=x11`).
- **A native view sits over the window's surface, not in it.** `NativeView(handle)` shows a platform view the app owns (an `NSView` on macOS: a web view, a map; `WebView` is its main tenant) where layout puts it; ziggui never draws it. Each frame the main window's context collects `NativeRegion`s (`Context.native_regions`, set by the loop only where `NativeBackend.presents`): the painter registers the frame, the visible part and corner radius and paints nothing, and `NativeBackend.present` frames the view there after the tree paints. On macOS (`AppKitNativeHost`) each view sits in a clipping container added to the content view *above* SDL's Metal view, so nothing ziggui paints can cover it: while an overlay is open (`OverlayRequest`s this frame, or the text context menu) every container is hidden, and the view that held the keyboard gets it back when the overlay closes. A view no `NativeView` showed this frame is hidden; one the app took out of its container drops its host. Clicks on a view are AppKit's and never SDL's: the container absorbs every mouse event its view passes up the responder chain (`absorb`), because `WKWebView` hands a click its page did not consume to its next responder, late, and reaching SDL that press left SDL thinking the button was down, so it dropped the next real click as a repeat. The loop also ignores any press inside a shown view (`contains`); a press elsewhere hands the keyboard back to SDL (`release`). SDL still sees every key, since `SDL3Application sendEvent:` feeds it each key event before AppKit routes it, so while a view holds the keyboard (`hasFocus`) the loop offers only ⌘/Ctrl keys to the app's key handler, and ⌘C/⌘X/⌘V/⌘A it does not consume, with no other modifier (⌃A moves to a field's line start; ⌘⇧V is another command), go to the view's first responder (`NativeBackend.performEdit`: `NSApp sendAction:` `copy:`/`cut:`/`paste:`/`selectAll:`, since AppKit gives the view no Edit menu) and drops every other key and typed text, which reach the view through AppKit. Those dropped keys wake no frame (`EventRouter.nativeKeyOnly`: an idle wait woken only by them keeps waiting), so typing in a web view never redraws ziggui. SDL's text input is stopped while a view holds the keyboard (`claim`): with it on, SDL runs `interpretKeyEvents:` on every key, which inserts through the first responder's input context, and the view then gets the key again from AppKit, so each character would land twice. The container's class (`ZigguiNativeContainer`) overrides `hitTest:` to claim when a hit test runs with a mouse button down (`+[NSEvent pressedMouseButtons]`; `currentEvent` there can be SDL's wake event), before the view takes the keyboard; each `present` claims too, for focus that came some other way. Claiming also clears ziggui's `Focus`: the press never reached ziggui, so its field would otherwise keep a caret, and take the keys once the view gives the keyboard back (under a sheet, say). `release` starts SDL's text input again, which makes SDL's text field first responder. Where nothing is collected (headless, a null handle, an OS with no host) it is a placeholder frame with a window glyph. Call `detachAll` before the window goes (the loop does); the app's views outlive it. Up to 16 views are placed at once. The host retains each placed view (the app may take it out and release it between frames) and the view it refocuses after an overlay; a press on a view that never takes the keyboard (a plain view) has SDL's text input started again at the next `present`, and `release` hands the keyboard to the content view (SDL's), holding no pointer to SDL's own field, which SDL frees as its text input stops. The gallery's Media Native section shows a tinted layer-hosting `NSView` in a window.
- **Singletons:** module-level state lives in a struct with a file-level instance and `pub fn shared() *Self` (`BuildScope`, `PointerInput`, `Focus`, `FrameClock`, `TextSelection`, `TextContextMenu`, `HelpTip`, `LayoutEngine`, `TextPainter`, `App`, `PopoverWindow`, `FileDialog`, `StatusItem`). Keep `threadlocal` where state was thread-local.
- **The ZIGSTYLE exception (C.1.a):** view constructors are free, PascalCase functions (`Chip(...)`, `HSplitView(...)`, `VStack(...)`). Only view constructors are exempt: every other function, private helpers included, is a method on a struct (a private struct like `Table`, `DiffModel` or `Entries` holds the helpers). Each file with view constructors opens with the `//!` doc, then `// zlint-disable case-convention` under a comment saying why.
- Enum variants are camelCase (C.2: `.hunkHeader`, `.chevronDown`, `.roundedRect`); zlint does not check this. SwiftUI's alignment constants keep SwiftUI's names (`Alignment.topLeading`). Struct-local test types (`Probe`) open with `const Self = @This();` too.
- No local aliases (B.4.a): write `renderer.Rect`, `mod.View`, never `const View = mod.View;`, and in tests `mod.SdlKey.left_alt`, never `const left_alt = mod.SdlKey.left_alt;` (`const allocator = std.testing.allocator;` is the guide's own test pattern and stays, as does an allocator or `io` bound the same way: `const allocator = std.heap.c_allocator;`, `const io = std.testing.io;`). A named, documented constant of a struct (`VideoPlayerControls.ink`) is not an alias. Imports go `std`, `log`, `mod`, then other modules (`renderer`, `views`, `sdl_c`) (B.2.b).
- Spell names out, locals, parameters and loop captures included: `title_bar_height`, `min_width`, `line_width`, `center_x`, `viewport_height`, `horizontalGradient`, `context`, `callback`, `environment`, `FrameSpecification`, never `title_bar_h`, `min_w`, `w`, `cx`, `hGradient`, `ctx`, `cb`, `env` or `FrameSpec`. A value is named for its type: a `renderer.DisplayList` is `display_list` (never `canvas`: a `Canvas` is the view that draws itself), a `GraphicsContext` is `graphics`, a `TestWindow` is `window`. Deliberate exceptions: `b: *std.Build` (every build script's convention), `catch |err|` and `io` (ZIGSTYLE's own idioms), `args` beside a `format` (std's `print` idiom), `x`/`y`, `T` for a comptime type, `Color`/`Rgba8`'s `r`/`g`/`b`/`a` fields (spelled out they would clash with `Color.red`/`green`/`blue`), SwiftUI names (`midX`), unit suffixes (`_ms`), and anything that mirrors a C, SDL, Win32, Objective-C or D-Bus name (`hdc`, `num_samplers`, `SdlKey.left_ctrl`).
- One primary public type per file, the file named for it in snake_case (`build_tokens.zig` → `BuildTokens`). Supporting types go above it, last the primary: the types that are part of its API (its fields', payloads' and items' types: `Kind`'s `*Data`, `DrawCommand`'s payloads, `DiffLineKind`, `MenuBarItem`, `CommandItem`), even when callers name them to build or read it. A type with a life of its own, used by several types, gets its own file. A widget file (`chat.zig`, `panes.zig`, `split.zig`, `menu_bar.zig`, `title_bar.zig`, `controls/*.zig`, `containers/*.zig`) holds view constructors and no public struct: a public type the constructors take gets a file of its own (`split_state.zig`, `navigation_path.zig`). A supporting enum used only by one constructor stays beside it (`StatusMarkState`, `WindowButtonStyle`). Every struct and enum opens with `const Self = @This();`. Methods take `*Self`, or `*const Self` when read-only, including on enums. Order: `init`, `deinit`, public API, then private helpers.
- A `.foregroundStyle()` sets `foreground` for its subtree, and `Context.tint` for its own view only (never inherited); the button painter draws a `.plain` button's label in `tint` when set, so `ButtonRoled("Delete…", .plain, …).foregroundStyle(red)` is a red, unfilled button, while a color on a pane or row leaves its plain buttons alone. Other roles keep their painter colors.
- Stack space (`SpaceDistributor`): items with a natural size (a truncating text) are offered the room first, beside the fillers' minimums; fillers (`FlexItem.fills`: a `Spacer`, a max-width frame, max ≥ `fill_threshold`) share what is left. So `HStack{ name.truncated(), Spacer(), badge }` shows the whole name when it fits, as SwiftUI does. A stack of only one kind shares as before.
- `init` builds a local `const self = Self{ ... };` and returns it. Types that hold pointers into themselves are heap-allocated with `create`/`destroy` (`TestWindow`, `EventLoop`).
- Import siblings only through the barrel. Compile-time invariants (`is_debug`) live in the barrels; never `@import("builtin")` elsewhere (`build.zig` asks `b.graph.host.result.os.tag` for the host) (executables read `gallery.is_debug`, and `gallery.is_macos` for the gallery's AppKit sample).
- View constructors allocate from `BuildScope.shared().allocator()` and read colors from `BuildScope.shared().tokens()`; they run once per frame inside `BuildScope.begin`/`end`, or at paint time inside a `GeometryReader`.
- Every file except `src/root.zig` declares `std.log.scoped(.ziggui_<file>)` (barrels `.ziggui_<dir>_module`; the gallery's files `.ziggui_gallery_<file>`, `gallery.zig` itself `.ziggui_gallery`). **The tracing exception (D.3.a):** only entry points (`main`, `App.run`, stateful `init`s, `Screenshot.render`) trace with `log.debug("{s}:{d} :: {s}", .{ @src().file, @src().line, @src().fn_name })`. View constructors and the per-frame methods they call would flood a Debug build's stderr every frame. A file with nothing to trace says so in its `test` block (`// Nothing here does I/O to trace.` and `_ = log;`).
- Errors: a view constructor cannot fail, so an allocation in the build arena ends `catch @panic("oom")` (the wrap cache's arena fallback too). Never swallow one with `catch ""`, `catch {}` or a fallback value: platform code that gives up on a failed allocation or copy logs it (`log.warn("…: {s}", .{@errorName(err)})`) before it returns null or false. A catch that maps "not a digit" or "not a lead byte" to a value is parsing, not swallowing, and `TtfFont` reads a malformed table as zero by design (a bad glyph draws empty). Format with `Allocator.print`, not the deprecated `std.fmt.allocPrint`.
- Every public declaration gets a `///` doc: struct fields, constants, and each barrel re-export included. Every function gets one too, private helpers, nested and anonymous structs' functions, callback trampolines and test helpers included. A function's doc (E.1.b) is a one-line summary, a blank `///`, one `` - `name`: `` bullet per named parameter (`self` too), then `- Returns:` whenever it returns a value. An error union counts (`- Returns: nothing; propagates allocation failure.`); a plain `void` function has no `Returns` line, and one whose parameters are all `_` has the summary alone. There is no `Parameters:` header. A function pointer field (`PlayerBackend`, `WebPageBackend`, `Painter`, `App`'s handlers) documents its parameters the same way, `Returns` included; a field that mirrors a C entry point or vtable slot (the `dlopen`ed `GtkApi`/`GstreamerApi`/libdbus tables, COM vtables) keeps its one-line `` `c_name` `` doc instead, its parameters unnamed.
- Tests go after the `// Unit Tests` divider. They use `std.testing.allocator`, `defer` every `deinit`, and start with `test { std.testing.refAllDecls(...) }`. Draw, tap and scroll with `mod.TestWindow` (`begin`, build, `end`, `render`, `tap`, `scroll(point, delta_x, delta_y)`), a headless window, its variable `window`; a `renderer.DisplayList` is held in one named `display_list`. A module's tests run only when it is a test root, which is why `build.zig` has one test compile per module.

## Zig 0.17 gotchas

- `@cImport` is gone: C headers go through `b.addTranslateC` and are imported as a module (`sdl_c`).
- **`@intCast` miscompile in Zig 0.17.0 (why `minimum_zig_version` is 0.17.1):** 0.17.0 emitted LLVM `trunc nsw` for `@intCast` from a signed integer to an unsigned one, a promise that the value also fits as a signed number, so a valid result in the top half of the unsigned range (128–255 in a `u8`) was poison and optimized builds folded code using it (`@as(u8, @intCast(@min(x, 200))) == 200` was false). The gallery's 18-section `Section` (5-bit tag, `.editor` = 17) hit it. 0.17.1 emits `trunc nuw`. If a ReleaseFast-only bug looks impossible, compare `--verbose-llvm-ir` against the Debug behavior.
- `zig fetch` and `zig build` can disagree on a tarball's hash when the cached tarball keeps its top-level folder; the `.sdl` hash in `build.zig.zon` is the one a clean fetch computes (`…LB1x…`, sources at the package root).
- `std.ArrayList(T)` is unmanaged (`.empty`, `append(allocator, x)`); `refAllDeclsRecursive` is gone; `std.process.Init` brings args and io to `main`; `allocator.dupeZ` is `dupeSentinel(u8, s, 0)`; array repetition is `@splat`.
- A type declared inside another type that has `Self` declares its own `Self` too, but where both are in scope a reference to `Self` is an "ambiguous reference": inside a generic's nested type (`MenuTable`'s `Entry`, `Choice`) name the types instead (`*const Entry`, `MenuTable(Context, Action)`). An enum method takes `self: *const Self` and switches on `self.*`.
- Inferred error sets plus recursion is a "dependency loop": recursive functions that allocate declare `std.mem.Allocator.Error!T`.
- `b.lazyDependency` is deprecated: use `b.dependencyLazy`.
- Other deprecations this code has met (A.1.a): `std.mem.indexOf*`/`lastIndexOf*` are `find*` (`find`, `findPos`, `findLast`, `findScalarLast`); `std.fmt.bufPrint`/`bufPrintSentinel` are `std.mem.print`/`printSentinel`; `std.meta.fieldNames(T)` is `@typeInfo(T).@"struct".field_names` (`@"enum"` for an enum: 0.17's type info has `field_names`, not `fields`); `b.dupeStrings` is `b.graph.dupeStrings`; `std.mem.copyForwards`/`copyBackwards` are `@memmove`, whose two slices must be the same length (`@memmove(items[start..][0 .. items.len - end], items[end..])`); `Cpu.Arch.isAARCH64` is `isAarch64`. The compiler does not warn: check `/// Deprecated` in the std source.

- Windows web view and video (`windows/media`, checked on Windows 11 with Zig 0.17.1): `WebView2Backend` needs no `WebView2Loader.dll` (used when it sits beside the executable); it finds the installed runtime's `EmbeddedBrowserWebView.dll` through `EdgeUpdateClientState{F3017226-…}BWebView` and calls its `CreateWebViewEnvironmentWithOptionsInternal`, as the loader does; user data goes to `%LOCALAPPDATA%<executable>WebView2`. Pages keep posting through `window.webkit.messageHandlers.<name>.postMessage`: a document-created script forwards each to `chrome.webview.postMessage` as JSON naming the bridge. An opaque-origin page (`data:`) posts as `about:blank` before WebView2 reports its address, so the origin check uses the address the latest `NavigationStarting` set out for. Checked by hand in the gallery (`make app`, the Media Video and Media Web sections): the start page loads inside its rounded, clipped region, typing in the page lands once and Send delivers the field through the bridge, a bad host shows its failure, and Apple's bipbop HLS sample plays (adaptive up to 1920×1080, its English audio track listed) with the controls drawn over the picture on both the GPU and the software path (`ZIGGUI_SOFTWARE=1`). Not yet tried by hand: Ctrl+C/V in the page, the page hiding under a sheet, back/forward/reload, bookmarks, full screen. On Windows `make` comes from `winget install ezwinports.make`; `make app ZIG=<path>` picks a compiler when an older Zig is first on `PATH`. A checkout under a long folder path can make `zig build test-sdl` fail to start its test binary (`FileNotFound`: the cache path passes 260 characters); a shorter checkout path, or running the binary from a short path, avoids it.
